# Pilot 0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship the approved pilot workflow with reported-power integration, full-battery references, reviewable endpoints and explicit target approval.

**Architecture:** Keep raw acquisition and the immutable archive intact. Add a pure reference-analysis module and a pilot workflow mixin; extend versioned metadata, API and frontend without duplicating integration logic.

**Tech Stack:** Python 3.13, Home Assistant integration, native JavaScript, unittest and node:test.

**Spec:** `docs/superpowers/specs/2026-10-09-pilot-integration-rest-reference-design.md`.

## Global Constraints

- Version and algorithm 0.5.0; metadata schema 6.
- `power_reported` integrates held observations but never recording gaps >120 s, backwards time, invalid power or restart gaps.
- Pilot basis defaults to `gross`; optional `no_load_corrected` requires an explicit suitable frozen reference.
- Rest reference: explicit post-repower confirmation, 5-minute warm-up, 30-minute analysis in three blocks.
- End suggestion: four consecutive 5-minute windows (20 minutes total); never auto-stop the pilot calibration.
- Manual approval is independent of validity, completion and source quality; one reviewed run suffices.
- Raw observations, hashes and private exports are preserved; private data remain outside git.
- Existing isolated checkout is used; no extra worktree. User authorized implementation and an installable update.

## Review Focus

- Missing or reset diagnostic energy counters must not stop reported-power sessions, but unavailable required power/switch must stop.
- Changes after approval must invalidate its exact decision, including endpoint, basis, reference and revision changes.
- Manual finish, stop, restart and storage failure must retain rest-reference attempts without silently approving them.
- Repower top-up energy and pre-confirmation samples must never enter the rest-reference analysis.
- Dense alternating quality segments must not exceed the browser's useful payload or conceal valid history.
